# Artifact Layout

Every tool image writes its outputs into a shared `$ARTIFACTS_DIR` volume.
The layout below is **mandatory** so that platform ingestion, the MCP server,
and Jenkins post-steps can reliably locate files without per-tool configuration.

```
$ARTIFACTS_DIR/                         # e.g. /artifacts  (Docker volume)
│
├── job-report.json                     # Top-level job report (job-report.schema.json)
│
├── manifest.json                       # Artifact manifest (artifact-manifest.schema.json)
│
├── results/
│   └── <tool-name>/
│       ├── tool-result.json            # Structured results (tool-result.schema.json)
│       ├── raw/                        # Raw tool output (SARIF, JSON, text, etc.)
│       │   └── <tool-specific-files>
│       └── evidence/                  # Supporting files (binaries, pcaps, logs…)
│           └── <tool-specific-files>
│
├── logs/
│   └── <tool-name>.log                # Human-readable run log
│
└── sbom/
    └── sbom.<format>                   # e.g. sbom.cyclonedx.json, sbom.spdx.json
```

## Field Descriptions

### `job-report.json`

Written by `common/emit-job-report.py` at the end of every tool run.
Contains top-level metadata: `job_id`, `tool`, `status`, `timestamp`,
and optional inline `results` and `artifact_manifest` objects.

### `manifest.json`

Enumerates every file under `$ARTIFACTS_DIR` that should be uploaded or
archived, with SHA-256 checksums and MIME types.

### `results/<tool-name>/tool-result.json`

Normalised findings in a common schema regardless of which tool produced them.
Downstream consumers read only this file; they do not need to understand each
tool's native output format.

### `results/<tool-name>/raw/`

Unmodified output from the tool (SARIF, CodeQL BQRS/SARIF, AFL crash list,
Gitleaks JSON, Syft JSON, etc.).  Preserved for audit and re-analysis.

### `results/<tool-name>/evidence/`

Binary artefacts referenced by findings: crashing inputs, PoC scripts,
patched binaries, network captures, symbolic-execution witnesses.

### `logs/<tool-name>.log`

Full stdout/stderr of the tool run, captured by the entrypoint wrapper.
Useful for debugging without needing to re-run the container.

### `sbom/`

Software Bill of Materials files generated by the `sbom` image.
Supported formats: `cyclonedx-json`, `cyclonedx-xml`, `spdx-json`.

## Conventions

* All timestamps are **UTC ISO-8601** (`2026-04-25T00:00:00Z`).
* All file paths inside JSON are **relative to `$ARTIFACTS_DIR`**.
* SHA-256 hex digests are lower-case, 64 characters.
* Tool names are lower-case, hyphen-separated (e.g. `c-cpp-analysis`).
* Each tool run appends to, never overwrites, the `logs/` directory.
